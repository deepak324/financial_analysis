M508 Big Data Analytics — NLP project¶

Project title: Consumer Financial Complaint Classification Using Natural Language Processing¶

1. Dataset selection and project objective Dataset: Consumer Financial Complaint Classification Using NLP. Source: Source: https://www.kaggle.com/datasets/shashwatwork/consume-complaints-dataset-fo-nlp

1.1 Business problem Banks and financial companies get thousands of complaints from people in writing regarding credit reports, debt collection, loans, cards and banking. Staff read each one, and currently determine which team to pass on to. As the volume increases, this will become slow and inconsistent which can result in a complaint going to different departments, depending on the reader.

This project develops an NLP system to predict most probable product category to route the complaints faster, as the text of the complaint is read.

1.2 Why NLP fits Complaints are free-text. The same issue is expressed in various ways by customers. NLP transforms the unstructured text into features to which a model can be trained.

Questions this project answers

  • If a person writes a complaint about a product, is it possible to predict the type of product from the text?
  • What is the best traditional model?
  • Is performance consistent in all categories? Areas of model failure:
  • Are there examples of when it could support staff with initial routing?

1.3 Objectives

  1. Explore and clean the data
  2. Check for imbalance, missing values and length of text.
  3. Train the TF-IDF model using the training dataset.
  4. Test the model with the test data.
  5. Train and test classifiers
  6. Assess using appropriate criteria
  7. Analyse errors
  8. Make practical business suggestions

The model only predicts the category. It does not determine whether a complaint is valid or what compensation is to be awarded.

2. High-Level System Design¶

The proposed NLP system aims to automatically classify consumer financial complaints into the appropriate product categories. This helps route complaints to the relevant teams for further review. The system follows a supervised text classification approach and consists of the following stages:

flowchart TD
    A["Raw Consumer Complaint Text"] --> B["1. Data Loading and Exploration"]
    B --> C["2. Text Preprocessing"]
    C --> D["3. Feature Extraction
TF-IDF"]
    D --> E["4. Model Training and Selection
Baseline and Machine Learning Models"]
    E --> F["5. Model Evaluation and Error Analysis"]
    F --> G["6. Complaint Prediction and Routing Suggestion"]
    
    G --> H["Suggested Product Category"]
    H --> I["Relevant Team Reviews Complaint"]

The system first loads and explores the complaint dataset, followed by text preprocessing and TF-IDF feature extraction. Different machine learning models are then trained and compared. The selected model is evaluated using classification metrics and error analysis. Finally, the system predicts the complaint category and suggests the appropriate routing team, while allowing human review where necessary.

# Clean the complaint text

def clean_text(text):
    text = str(text).lower()

    # Replace URLs with a common marker.
    text = re.sub(
        r"https?://\S+|www\.\S+",
        " URL ",
        text
    )

    # Replace repeated whitespace with a single space.
    text = re.sub(r"\s+", " ", text)

    return text.strip()


data["text_clean"] = data["text"].apply(clean_text)

8. Feature engineering with TF-IDF¶

Models need numbers, not raw text. TF-IDF weights words that appear often in one complaint but rarely across the whole set. Both single words (unigrams) and word pairs (bigrams) like “late payment” are used to allow the model to capture useful short phrases.

9.1 What are the reasons for using a majority baseline?

If one of the categories is very common, and always predicting that category might result in reasonable accuracy without reading any text. The real models must outperform this value to demonstrate the complaint text.

from sklearn.model_selection import StratifiedGroupKFold, cross_validate

    n_splits=3,
    shuffle=True,
    random_state=42
)

scoring = {
    "accuracy": "accuracy",
    "macro_f1": "f1_macro",
    "weighted_f1": "f1_weighted"
}

14. Critical discussion¶

Overall performance¶

Linear SVM beat the majority baseline clearly (macro-F1 ≈ 0.86 on the test set). That shows the complaint text does contain useful signals. Performance is not equal across categories — the majority class is easier, while smaller classes are harder.

Strengths¶

  • Clear, measurable task
  • TF-IDF is simple and effective for this size of data
  • Baseline + several models give a fair comparison
  • Confusion matrix and error analysis show where the system fails

Limitations¶

  • Class imbalance hurts minority categories
  • Language overlaps (credit reporting vs debt collection)
  • Labels may contain errors
  • Customer language changes over time
  • Privacy: complaint text can contain sensitive data
  • Good test scores do not automatically mean lower cost or happier customers in production

Business recommendations¶

  1. The model is only a suggestion and staff should still verify the category
  2. Measure per category precision and recall, not just overall accuracy
  3. Review most common error pairs and fix labels where possible
  4. Re-train when products or languages change
  5. Protect personal data
  6. Run a small pilot first to measure actual impact on routing time and workload

15. Conclusion¶

Financial firms need a faster way to route written complaints. This project turned complaint text into TF-IDF features and compared a majority baseline, Naive Bayes, Logistic Regression and Linear SVM.

Linear SVM performed best (≈ 0.85 macro-F1 in CV, 0.86 on the test set, 89 % accuracy). It clearly beat the baseline. The main confusions were between credit reporting and debt collection, often caused by short text or overlapping language.

In a real setting the model should only suggest a category. Staff review, per-class monitoring, clean training data and a proper pilot are all needed before claiming business benefits. Overall the results show that complaint text is useful for automatic sorting, but human oversight remains essential.

The GridSearchCV experiment achieved a macro-F1 score of 0.8408 with C = 4.0. However, it did not improve upon the Linear SVM comparison result. Therefore, Linear SVM was retained as the final model for the complaint classification application.

def predict_complaint(text, confidence_threshold=0.60):

    if not text or text.strip() == "":
        return "Please enter a complaint text."

    # Predict complaint category
    prediction = ui_model.predict([text])[0]

    # Get calibrated probability estimates
    probabilities = ui_model.predict_proba([text])[0]
    confidence = float(np.max(probabilities))

    if confidence >= confidence_threshold:
        decision = (
            f"High confidence ({confidence:.2%}) "
            "— Suggested for automatic routing"
        )
    else:
        decision = (
            f"Low confidence ({confidence:.2%}) "
            "— Human review recommended"
        )

    result = f"""
### Predicted Category: {prediction}

**Confidence:** {confidence:.2%}

**Routing Decision:** {decision}
"""

    return result
