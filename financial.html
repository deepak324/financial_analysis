M508 Big Data Analytics — NLP project¶

Project title: Consumer Financial Complaint Classification Using Natural Language Processing¶

1. Dataset selection and project objective Dataset: Consumer Financial Complaint Classification Using NLP. Source: Source: https://www.kaggle.com/datasets/shashwatwork/consume-complaints-dataset-fo-nlp

1.1 Business problem Banks and financial companies get thousands of complaints from people in writing regarding credit reports, debt collection, loans, cards and banking. Staff read each one, and currently determine which team to pass on to. As the volume increases, this will become slow and inconsistent which can result in a complaint going to different departments, depending on the reader.

This project develops an NLP system to predict most probable product category to route the complaints faster, as the text of the complaint is read.

1.2 Why NLP fits Complaints are free-text. The same issue is expressed in various ways by customers. NLP transforms the unstructured text into features to which a model can be trained.

Questions this project answers

  • If a person writes a complaint about a product, is it possible to predict the type of product from the text?
  • Whuch traditional model perform best?
  • Is performance consistent in all categories?
  • What types of complaints are most frequently misclassified?
  • Could the model support staff with initial complaint routing?

1.3 Objectives

  1. Explore and clean the data
  2. Check for imbalance, missing values and length of text.
  3. Train the TF-IDF model using the training dataset.
  4. Test the model with the test data.
  5. Train and test classifiers
  6. Assess using appropriate criteria
  7. Analyse errors
  8. Make practical business suggestions

The predicted category can help staff identify the appropriate team for further review.

2. High-Level System Design¶

The proposed NLP system aims to automatically classify consumer financial complaints into the appropriate product categories. This helps route complaints to the relevant teams for further review. The system follows a supervised text classification approach and consists of the following stages:

flowchart TD

    C --> D["3. Feature Extraction
TF-IDF"]

    E --> F["5. Model Evaluation and Error Analysis"]

    G --> H["Suggested Product Category"]
    H --> I["Relevant Team Reviews Complaint"]

The system first loads and explores the complaint dataset, followed by text preprocessing and TF-IDF feature extraction. Different machine learning models are then trained and compared. The selected model is evaluated using classification metrics and error analysis. Finally, the system predicts the complaint's product category, which can support staff when deciding which team should review the complaint.

6. Text preprocessing¶

In this section, I use light text preprocessing. Lowercasing and cleaning URLs is beneficial for consistency but not doing it too aggressively can lose meaning (e.g. “not authorised”). Product names and financial terms are sometimes helpful indicators and they remain.

# Clean the complaint text

def clean_text(text):
    text = str(text).lower()

    # Replace URLs with a common marker.
    text = re.sub(
        r"https?://\S+|www\.\S+",
        " URL ",
        text
    )

    # Replace repeated whitespace with a single space.
    text = re.sub(r"\s+", " ", text)

    return text.strip()


data["text_clean"] = data["text"].apply(clean_text)

7. Divide data into training data and test data¶

The dataset is divided into training and testing sets using an approximately 80:20 ratio. StratifiedGroupKFold maintains a similar category distribution while keeping identical complaint narratives in the same group. This helps reduce the risk of data leakage.

8. Feature engineering with TF-IDF¶

Models need numbers, not raw text. TF-IDF weights words that appear often in one complaint but rarely across the whole set. Both single words (unigrams) and word pairs (bigrams) like “late payment” are used to allow the model to capture useful short phrases.

TF-IDF Feature Extraction¶

TF-IDF converts the complaint text into numerical features that machine learning models can understand. In this demonstration, the vectorizer is fitted on the training data and then applied to the test data using the same vocabulary.

The TF-IDF matrices created in this section are used to demonstrate feature extraction. The actual model training in Section 9 uses separate TF-IDF vectorizers within each machine learning pipeline. This ensures that the vocabulary is learned from the training portion of each cross-validation fold, helping to avoid data leakage during model evaluation.

9.2 What are the reasons for using a majority baseline?

The majority baseline always predicts the most common complaint category without analysing the complaint text. It provides a simple reference point for evaluating the other models. The machine-learning models should perform better than this baseline to demonstrate that the complaint text contains useful information for predicting product categories.

# Compare models using group-based cross-validation

from sklearn.model_selection import StratifiedGroupKFold, cross_validate

cv = StratifiedGroupKFold(
    n_splits=3,
    shuffle=True,
    random_state=42
)

scoring = {
    "accuracy": "accuracy",
    "macro_f1": "f1_macro",
    "weighted_f1": "f1_weighted"
}

cv_results = []

for name, model in models.items():
    print("Evaluating:", name)

    scores = cross_validate(
        model,
        X_train,
        y_train,
        groups=X_train,
        cv=cv,
        scoring=scoring,
        n_jobs=-1,
        return_train_score=False
    )

    cv_results.append({
        "model": name,
        "mean_accuracy": scores["test_accuracy"].mean(),
        "mean_macro_f1": scores["test_macro_f1"].mean(),
        "std_macro_f1": scores["test_macro_f1"].std(),
        "mean_weighted_f1": scores["test_weighted_f1"].mean()
    })

cv_table = pd.DataFrame(cv_results).sort_values(
    "mean_macro_f1",
    ascending=False
)

from sklearn.model_selection import GridSearchCV, StratifiedGroupKFold

lr_pipeline = Pipeline([
    ("tfidf", TfidfVectorizer(

tuning_cv = StratifiedGroupKFold(

grid_search = GridSearchCV(
    estimator=lr_pipeline,
    param_grid=parameter_grid,
    scoring="f1_macro",

    verbose=1
)

Tuning result
GridSearchCV tested three regularisation values (0.25, 1.0 and 4.0) for Logistic Regression using three-fold cross-validation. The best parameter was C = 4.0, which achieved a macro-F1 score of 0.8416. This improved the original Logistic Regression result of 0.8374. However, it remained slightly below the Linear SVM cross-validation score of 0.8446. Therefore, Linear SVM was retained as the final model.

14. Critical Discussion and Business Recommendations¶

Overall performance¶

The Linear SVM model achieved a test accuracy of 86.21% and a macro-F1 score of 0.8470. Its cross-validation macro-F1 score was 0.8446. It performed considerably better than the majority baseline, which achieved a macro-F1 score of 0.1246 during cross-validation. This indicates that complaint text contains useful information for predicting financial product categories.

Performance was not equal across all categories. Credit reporting achieved the highest F1-score of 0.90, while debt collection achieved the lowest at 0.80. This suggests that some product categories are more difficult to distinguish.

Strengths¶

  • The project addresses a clear business problem.
  • TF-IDF provides a simple way to convert complaint text into numerical features.
  • Four different approaches were compared using cross-validation.
  • The selected model was evaluated on a separate test dataset.
  • The confusion matrix and error analysis helped identify common classification mistakes.

Limitations¶

  • The dataset originally contained class imbalance, and its category distribution changed after duplicate removal.
  • Some categories have overlapping complaint language, particularly credit reporting and debt collection.
  • A total of 172 unique narratives had conflicting product labels, so the associated 376 records were excluded from modelling.
  • The source dataset appears to contain text that has already been processed. This may create a difference between the training text and new, naturally written complaints entered through the application.
  • Customer language and financial products can change over time, which may affect model performance.
  • Complaint narratives may contain sensitive personal information and must be handled carefully.
  • The test results do not demonstrate actual reductions in complaint-routing time, staff workload or business costs.

The probability estimates displayed in the interactive application have not been independently evaluated for reliability in this project. The selected 60% threshold is therefore a demonstration setting rather than a validated business decision threshold.

Business recommendations¶

The model should be used as a decision-support tool rather than an automatic replacement for staff.

Staff should verify the predicted category before taking action. The organisation should monitor precision and recall for each category, review common classification errors and update the model when complaint patterns change. Personal information should be protected, and a small pilot should be conducted to measure whether the system improves routing time and workload.

15. Conclusion¶

Financial companies receive many written complaints, and classifying them manually can take time. This project explored whether Natural Language Processing and traditional machine-learning methods could help predict the product category from complaint text.

The dataset was cleaned by removing duplicate records and excluding complaints with conflicting product labels. TF-IDF was then used to convert the complaint text into numerical features. Four approaches were compared: a majority baseline, Naive Bayes, Logistic Regression and Linear SVM.

Linear SVM achieved the best cross-validation macro-F1 score of 0.8446. On the separate test dataset, it achieved 86.21% accuracy and a macro-F1 score of 0.8470. The most common classification errors occurred between credit reporting and debt collection.

The results indicate that complaint text contains useful information for predicting product categories. However, the model does not classify every complaint correctly and should not make final routing decisions without staff verification. Further testing with new complaints and a practical pilot would be necessary before using the system in a real financial organisation.

def predict_complaint(text, confidence_threshold=0.60):

    if not text or text.strip() == "":
        return "Please enter a complaint text."

    # Apply the same cleaning function used during training
    cleaned_text = clean_text(text)

    if cleaned_text == "":
        return "Please enter valid complaint text."

    # Predict the product category
    prediction = ui_model.predict([cleaned_text])[0]

    # Obtain estimated probability
    probabilities = ui_model.predict_proba([cleaned_text])[0]
    confidence = float(np.max(probabilities))

    # Provide review guidance
    if confidence >= confidence_threshold:
        decision = (
            "Stronger model signal. "
            "Staff verification is still required."
        )
    else:
        decision = (
            "Lower model signal. "
            "Human review is recommended."
        )

    result = f"""
### Predicted Product Category: {prediction}

**Estimated probability:** {confidence:.2%}

**Review guidance:** {decision}

*Note: This is a model prediction and should not be treated
as a confirmed complaint classification.*
"""

    return result
